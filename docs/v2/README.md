# v2 リファクタリング 引き継ぎ資料

このディレクトリは、v2 の実装を担当するエージェント(と人)向けの資料です。
方針はユーザと合意済みです。ここに書かれた範囲で実装を進めてください。

## 目的

利用者のセットアップの手間を減らし、複数の mirakc / Mirakurun につなげるようにする。あわせて、上流の変更でビルドが壊れても利用者に届かない構造にする。

1. EDCB の設定を起動時に自動で整える(プロビジョニング)
2. 複数バックエンド(コンテナ外の mirakc / Mirakurun を含む)に対応する
3. チャンネル定義の作成と、地上波用 / 衛星用への分割を自動化する
4. 上流のバージョンをタグとコミットで固定し、CI で検証し、ビルド済みイメージを配布する

## 読む順番

1. `decisions.md` — 合意済みの方針。**ここは勝手に変えない**
2. `facts.md` — 上流ソースで確認済みの事実と、未確認の点
3. `design.md` — 目標仕様
4. `phases/` の担当フェーズのファイル

## フェーズと状態

フェーズは番号順に進める。前のフェーズが `v2` ブランチに入ってから次に着手する。

| # | ファイル | 内容 | 状態 |
|---|---|---|---|
| 1 | `phases/1-build.md` | 上流の固定、パッチの当て方、CI、compose の git 管理 | 完了 |
| 2 | `phases/2-provision.md` | プロビジョニングの基盤、実行ユーザ、ヘルスチェック | 完了 |
| 3 | `phases/3-backends.md` | BonDriver の修正、複数バックエンド、チューナー数の自動設定 | 完了 |
| 4 | `phases/4-channels.md` | チャンネルスキャンの自動化、S/T 分割、`edcbctl` | 完了 |
| 5 | `phases/5-mirakc.md` | ベースイメージと依存の更新、mirakc コンテナの pcscd 切り替え、ハードウェアエンコードの見本、HLS 方式の視聴、外した接続先の片付け(`edcbctl prune`) | 完了 |

## 進め方のルール

### ブランチ

- 統合先は `v2` ブランチ(無ければ `main` から作る)。v2 が完成するまで `main` には入れない。
- 1 フェーズ = 1 作業ブランチ(`v2-phase-1-build` など)。コミットは作業ブランチに行う。
- push、PR 作成、タグ、GHCR 公開は、ユーザの指示があるときだけ行う。

### 触ってはいけないもの

- `edcb/ini/`、`mirakc/config.yml`、未追跡の `compose.yml` は利用者の実データ。書き換えない。
- リポジトリ直下で `docker compose up/down/restart` を実行しない。稼働中の録画が止まる。
- 検証は一時ディレクトリにコピーした構成で、`docker compose -p edcbtest` のように別プロジェクト名、別ポートで行う。
- 上の 2 つは既定の扱い。ユーザから「この環境のデータは壊してよい」「止めてよい」と明示的に伝えられている場合は、その範囲で実データや直下の構成を使ってよい。
- 許可がある場合でも、Docker のコマンドはこのリポジトリが作ったコンテナ、イメージ、ボリュームだけを対象にする。同じホストで別のコンテナが動いていることがあるので、`docker system prune` のようなホスト全体に効くコマンドは使わない。

### Docker を実行できないとき

環境によっては、エージェントが Docker デーモンを使えない(権限が無い)ことがある。そのときは次のようにする。

- デーモンが要らない確認(`docker compose config`、pytest、シェルスクリプトの構文確認など)は自分で行う。
- デーモンが要る確認(`docker build`、`docker run`、`docker compose up`)は、実行するコマンドを順番にまとめてユーザに依頼し、出力を受け取ってから結果を判断する。往復を減らすため、1 回分の確認は 1 つのスクリプトにまとめ、出力をファイルに残す形にする。繰り返し使う確認は `tests/integration/` に入れる(「検証の道具」)。
- 依頼した確認の結果が出るまで、その受け入れ条件は「未確認」として扱う。

### 検証の道具

フェーズをまたいで使う確認は、リポジトリに入っている。フェーズで確認を足すときは、スクラッチに置かず、ここに足すこと。

| 道具 | 内容 | Docker デーモン |
|---|---|---|
| `scripts/check.sh` | pytest、shellcheck、actionlint、`docker compose config`、文書のリンク(`scripts/check-links.py`)、環境固有の情報の混入チェック。CI の `check` ジョブと同じもの。shellcheck と actionlint は `scripts/install-tools.sh` で `.tools/` に入る | 不要 |
| `tests/integration/run.sh` | イメージをビルドし、コンテナを起動して確かめる結合テスト。使い方は `tests/integration/README.md`。root で実行する(`sudo tests/integration/run.sh`)。結果はログに `RESULT <番号>: PASS / FAIL / SKIP` で残る。CI でも実行する | 必要 |
| `scripts/check-local-info.sh` | 環境固有の情報(ホームディレクトリのパス、ホスト名、LAN のアドレスなど)がコミットに入るのを止める。`git config core.hooksPath scripts/git-hooks` で、コミット時に自動で動く。その環境だけの禁止パターンは、git 管理外の `.local-info-patterns` に書く(1 行に 1 つの拡張正規表現) | 不要 |

- コミットの前に `scripts/check.sh` を通す。
- entrypoint、プロビジョニング、Dockerfile を変えたフェーズでは、`tests/integration/run.sh` を全項目実行し、そのフェーズの確認を `tests/integration/phase<番号>.sh` に足す。
- 検証の手順やテスト用のデータに、特定の環境の情報(パス、プロジェクト名、アドレス、チャンネル構成)を書かない。

### 判断に迷ったとき

- `decisions.md` と食い違う実装が必要になったら、進めずにユーザへ確認する。
- `facts.md` の「未確認」に当たる点は、まず自分で確認する(上流ソースを読む、小さく試す)。確認できたら `facts.md` を更新する。
- `facts.md` の「確認済み」が誤っていた場合は、`facts.md` を直し、設計に影響するならユーザへ報告する。
- チューナー実機が要る確認は自分ではできない。フェーズファイルの「実機確認の依頼」に手順を書き、ユーザに依頼する。

### 完了の基準

- フェーズファイルの「受け入れ条件」をすべて満たす。満たせなかった条件は、理由とともに「実施記録」に書く。
- 「検証」に書かれたコマンドを実際に実行し、結果を「実施記録」に残す。実行していない検証を「通った」と書かない。
- フェーズファイル末尾の「実施記録」に、行ったこと、設計から変えた点、次のフェーズへの申し送りを書く。

## ユーザの作業が必要なもの

エージェントだけでは完了できない作業です。該当フェーズで必要になったら依頼してください。

| 作業 | 必要になる時点 | 内容 |
|---|---|---|
| BonDriver のフォーク作成 | フェーズ 3 | `gh repo fork matching/BonDriver_LinuxMirakc`。作成までは、このリポジトリ内のパッチで進める |
| 再配布条件の確認 | フェーズ 6(GHCR 公開の前) | EDCB と EMWUI にはライセンス表記が見当たらない(`facts.md` 参照)。公開するかはユーザが決める |
| GHCR パッケージの公開設定 | 初回リリース時 | パッケージを public に変更する |
| 自動 PR 用のトークン | フェーズ 1 の定期チェックを有効にするとき | 標準トークンで作った PR は CI を起動しないため |
| 実機での確認 | フェーズ 2〜5 | HTTPS での視聴、ホスト名接続、チャンネルスキャン、ホストの pcscd ソケット、Intel GPU でのトランスコード |

## エージェントへの依頼文の例

```
docs/v2/README.md を読み、フェーズ 1(docs/v2/phases/1-build.md)を実装してください。
作業ブランチは v2-phase-1-build です。受け入れ条件をすべて満たし、検証結果を実施記録に書いてください。
push と PR 作成はしないでください。
```
